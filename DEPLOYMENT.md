# Deployment

There is no server here — this repo ships two static, generated artifacts:
`registry.json` (the in-app directory) and `plugins/` +
`.claude-plugin/marketplace.json` (the Claude Code bundles). "Deploying" means
making those fetchable over the network instead of only from a local path.

## Making the repo public

The remote (`vinnovateit/studyhub-skills`) exists on GitHub but its
visibility is not something to flip from a script — do that deliberately in
the repo's GitHub Settings → General → Danger Zone. Confirm first:

- `LICENSE` (MIT) is committed and accurate.
- No secrets in history — this repo has never held any (no `.env`, no
  credentials), but check before flipping visibility since it's very hard to
  fully undo afterwards.

## Consuming it remotely once public

**Plugin marketplace** (any Claude Code install, not just this checkout):

```sh
claude plugin marketplace add vinnovateit/studyhub-skills
claude plugin install exam-prep
```

**Raw registry.json**, for the in-app directory or any other consumer:

```
https://raw.githubusercontent.com/vinnovateit/studyhub-skills/main/registry.json
```

Each entry's `SKILL.md` is fetchable the same way, e.g.:

```
https://raw.githubusercontent.com/vinnovateit/studyhub-skills/main/skills/exam-prep/SKILL.md
```

Both assume `registry.json` and `plugins/` are checked in up to date — see
below.

## Keeping generated output in sync

`registry.json`, `plugins/`, and `.claude-plugin/marketplace.json` are
generated by `scripts/build.mjs`, committed in place (there is no separate
build/publish step — what's on `main` is what a remote consumer fetches).
Before merging or tagging a release:

```sh
npm run build   # regenerates registry.json, plugins/, marketplace.json
npm test        # validate + check + check-pr + check-review-accesses + determinism
```

`npm run check` (part of `npm test`) fails if committed generated output has
drifted from source — that's the signal a deploy would ship something stale.

## CI

`.github/workflows/ci.yml` runs `validate` and `check` on every PR. It's free
and unmetered once the repo is public — no separate action needed to "enable"
it beyond the visibility change above.
